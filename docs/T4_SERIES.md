各模块自带对应测试，不把回归全部推迟到最后一项。
第四项的 155 项包含当时工作树内已补充的 8 项共存门禁；这些门禁文件放在第五提交，
所以“阶段验证工作树”不等于“仅检出第四提交的测试数量”。
第一项是可独立运行的协议 PR；其余按模块分别开放依赖草稿，便于提前 review。
每个草稿均基于公开 `main`，只包含自身补丁，不累计包含前序提交。
分支分别为 `codex/t4-media`、`codex/t4-browse`、`codex/t4-host-ui`、
`codex/t4-validation`。这些独立补丁有前置依赖，不能单独运行或越序合入。

集成验证分支 `codex/t4-pr-validation` 从协议层开始，逐一应用各草稿的实际补丁，
用来验证组合结果；原 `codex/t4-modular` 快照不改写。
前序合入后，将下一草稿合并更新到届时最新 `main`，重新验证再转为正式审核。
不强推改写已经发布的模块分支，不修改原 #57 历史。

CI 对依赖草稿跳过合同测试，这代表“未执行”，不是“测试通过”。
完整集成分支推送及非草稿 PR 才执行合同测试；`ready_for_review` 会触发验证。

## 对维护者重点的回应

| 反馈 | 当前措施 | 仍待验证 |
| --- | --- | --- |
| 大提交/回滚粒度 | 首个协议 PR 与四个独立模块草稿，无累计差异 | 按依赖顺序更新基线、复验、转为正式审核 |
| 无 T4 零工作量 | 无对象创建/状态读取/网络/探测任务，纯 CMS 使用原调度 | 真 NAS 空配置观察，见共存说明的准确承诺 |
| `/seg`、占位、自动换线交叉 | 按目标类型分支，T4 资源路径/会话独立，不自动跨 CMS | 上游未公开的新自动换线契约 |
| 搜索扇出 | 混合交替调度 8 路、预算取消；纯 CMS 不换调度器 | NAS 网络与大订阅实测 |
| 首字节 3 秒 | 明确当前 10 秒识别/8 秒元数据预算的差距，不声称已达标 | 三端记录实际媒体首字节与首画面 |
| Unix socket 接管 | 不改接管部署脚本 | NAS 启停/升级/卸载 |
| 媒体库注入/权限 | T4 库与目录权限沿用上游账号可见性 | 当前客户端与分用户验证 |
| 分用户历史 | 保留上游用户桶，T4 显式选择最近交互续播 | A/B 账号真机续播隔离 |

共享 TV 日期/状态归一是明确的响应层修正，不能声称普通 CMS 所有输出逐字节不变。
NAS、App Android/iOS、TV、Web、首字节目标均未在本模块化分支实机验收。
