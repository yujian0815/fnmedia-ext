# T4 与普通 CMS 并存：选路、交付和回退

## 适用基线

这是 PR #57 的模块化后续方案，基于公开 `main`
`28d35835c9766c2ad0a7c2812b912951e7430156`（2026-11-03）。
不改变上游版本号、更新源、维护者或打包标识。
维护者提及但尚未出现在公开源码中的内部新能力，仍需在集成分支逐项对照，
不能以“没有文本冲突”代替语义回归。

## 选路顺序

| 阶段 | 普通 CMS | 远程 T4 |
| --- | --- | --- |
| 来源识别 | 原来源与原配置 | 订阅 `type=4` 导入为 `kind=t4` |
| 全局搜索 | 无启用 T4 时沿用原 CMS fan-out/单源软超时 | 混合时 CMS/T4 交替排队，最多 8 路；按搜索预算保留已完成结果 |
| 搜索身份 | 保留原 CMS 合并策略 | 独立来源及稳定内容 ID，不因同名并入 CMS 线路 |
| 目录/详情 | 原 CMS 分类/详情路径 | 列表不取播放地址；点击才加载详情，网盘目录按需展开 |
| 播放目标 | 原 `direct/resolve/redirect` | `target.t4` 明确进入 T4 分支，向远端 `player` 取链 |
| 热门库/深分类 | 保留原刷新任务 | 排除 T4，不在后台全量展开插件或网盘 |
| 预热 | 原 CMS playlist 预热 | `_warm_playlist` 直接短路 |
| 解码 | 客户端 | 客户端；扩展不转码、不重封装 |

启用 T4 会在混合搜索中有意调整扇出预算；禁用的 T4 不触发混合调度。
`sources=[]` 保持空列表，不意外恢复默认 CMS 来源。

## 媒体交付矩阵

| T4 结果 | 实际交付 | 与 `/seg` 的关系 |
| --- | --- | --- |
| 公网、无附加请求头 MP4/MKV | 完成有限格式识别后，交原始地址给客户端 | 不进入 `/seg` |
| 私网/回环，或必须携带 Cookie/Referer 等请求头 | 扩展按请求流式转发，私有头保留在服务端 | 独立 `/v/media/online/{media_guid}/t4` |
| 公网无头 HLS | 使用独立播放会话入口，再 302 到原清单 | 不接 CMS 清单重写链 |
| 私网/带头 HLS | 改写主/子清单、音轨、密钥及分片相对 URI | 独立 `/v/media/t4-resource/{token}` |
| `parse/jx` 未完成、DASH/双轨或非媒体 HTML | 明确错误 | 不伪装 CMS、占位媒体或已成功播放 |

流式路径透传 Range/If-Range，保留 HEAD、206、416 及 Content-Range 语义，
不整片读取；客户端断开时关闭上游。嵌套 HLS 保留相同 URI 的 BYTERANGE 身份。
HEAD 只提供响应头，实际播放格式不能仅靠 HEAD 或 `.mp4` 后缀判定。
现有 CMS `/seg` 路由及其占位、竞速、自动换线实现不由 T4 代管。

媒体重定向不等于客户端可达：公网域名若只在 NAS 可访问，需由 T4 服务端提供合适
的代理结果。当前私网判断基于 URL 主机字面量/本地域名，不是所有 DNS/VPN 拓扑的
可达性探测，也不承诺对任意公网域名自动加速。

## 回退与错误边界

1. T4 详情或 player 返回可刷新错误（部分 HTTP 400/404）时，按同一稳定身份刷新详情，
   最多重取一次；不按片名盲搜恢复已失效的临时 ID。
2. 取链短缓存只在内存；详情刷新清除关联播放缓存，交付失败使该取链缓存失效。
3. T4 同片换线只匹配明确季集键，不按数组位置补缺集；每个 HLS 播放会话独立。
   换线后媒体类型改变时要求重新播放，不伪报热切成功。
4. **T4 失败不会自动搜索 CMS 并切过去**。用户可返回搜索结果，显式选普通 CMS 卡片。
   CMS 原自动换线继续只管理自己的候选线。
5. 不将 T4 取链错误送入 CMS 占位清单、`/seg` 自救或线路竞速；不把 HTTP 200 当解码成功。
6. 停用来源后拒绝从其缓存目录取新内容；已交给客户端的媒体 URL 不构成可撤销授权。

## 无 T4 时的开销承诺

承诺对象是可验证的 T4 工作量，不是“Python 连一个条件判断都不执行”：

- 应用 import 不实例化 `T4Service/T4Media/T4Browser`，不读取 T4 浏览状态文件。
- 普通 CMS 详情在进入 T4 服务前返回；普通搜索不使用 T4 的 8 路调度器。
- 无 T4 来源不产生 T4 HTTP、媒体探测、后台任务或 T4 状态写入。
- 未建立的 T4 资源会话直接返回过期/不存在，不因此初始化运行时。
- 进程曾使用 T4 后停用来源时，已有有界内存对象可能仍存活；本承诺不等于
  即时卸载 Python 模块或回收所有历史对象。

`tests/test_t4_coexistence.py` 覆盖初始化、来源停用、普通详情、空入口、
CMS fan-out/软超时、CMS 季集形态、续播顺序及 T4 不预热。
另有共享的 TV 日期/状态归一修正，属于明确的响应兼容变更，需在 CMS 真机基线中复验，
不宣称所有普通 CMS 响应字节完全不变。

## 性能预算与未过门禁

- 搜索：含 T4 时调用方使用 5 秒聚合预算，最多 8 并发；超时保留已完成结果并取消剩余。
- 浏览：最多 4 路，单次 35 秒上限；缓存 32 项/4 MiB，目录身份最多 2048 项。
- 格式识别：每个短期播放结果最多读取 4 KiB，但 HTTP 超时仍为 10 秒。
- 可选元数据：最多 8 MiB、8 秒、两路并发；超出前台预算延后，关闭时取消并回收子进程。

**有限字节不等于 3 秒首字节。当前没有所有 T4 来源均在 3 秒起播的保证。**
真机应分别记录取链、格式识别、元数据准备、实际首媒体字节和首画面时间。
若上游 0.2.66 集成要求首字节硬限 3 秒，本系列目前仍为待验收状态，
不能通过改小文档中的数字或用回环 Mock 冒充已达标。

## 回滚粒度

先撤销宿主接入与 UI，停止注册 T4 入口；纯模块可保留但不会自动启动。
再按反向依赖移除浏览状态、媒体交付、协议层。保留用户 CMS 配置和上游历史。
T4 短期会话不承诺跨进程恢复；再次启用后重新选片取链。
